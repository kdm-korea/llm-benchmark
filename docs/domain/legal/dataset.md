# 법률 도메인과 평가 데이터

## 데이터 출처와 현재 상태

[제공 계획서](../../references/legal_embedding_recall_benchmark.md)에 따라 [EVE-Bench-Legal-2.0](https://huggingface.co/datasets/ysmeta/EVE-Bench-Legal-2.0)을 사용할 예정입니다. 제공된 MD는 실험 계획서이며 판례 Corpus가 아닙니다.

공식 API와 README를 조회하고 고정 리비전의 Corpus와 Qrels를 다운로드했습니다. [확인 기록](data-inspection-2026-10-19.md)에 실제 필드·크기·중복 질의·해시를 남겼습니다. 아래는 구현에 사용한 내부 형식입니다.

## 내부 데이터 역할

| 데이터 | 내부 역할 |
| --- | --- |
| Corpus | 고유 문서 ID, 제목(존재할 경우), 판례 본문 |
| Queries | 고유 질의 ID와 질의 텍스트 |
| Qrels | 질의 ID → 문서 ID와 관련성 등급 |

1차는 판례 1개를 하나의 검색 문서로 유지하고 벡터 1개를 생성합니다. 원본 `title`과 `text`의 앞뒤 공백을 제거하고 비어 있지 않은 문자열을 줄바꿈으로 결합해 모델 간 동일하게 적용합니다. 모델별 토큰 제한에 따른 잘림은 별도로 기록합니다.

## 정합성 검증

- Corpus와 Queries의 ID 유일성, 비어 있는 텍스트 여부를 확인합니다.
- Qrels의 질의·문서 ID가 해당 데이터에 존재하는지 확인합니다.
- ID를 문자열 등으로 정규화할 때 충돌이나 선행 0 손실이 없는지 확인합니다.
- 동일 질의가 여러 행에 있으면 설정에 명시한 `merge_max`로 문서 합집합과 최대 등급을 보존하고 병합 이력을 남깁니다. 엄격 모드 `error`에서는 중단합니다.
- 평가 분할과 리비전을 고정하고 전체 Corpus를 검색 대상으로 사용합니다.

## 정답 규칙과 한계

Qrels relevance > 0인 문서를 관련 문서로 간주합니다. 원본 `grades`의 수치 등급을 보존하고 Recall에는 양수 여부만 사용합니다. 관련 문서가 없는 질의는 평가에서 제외하고 사유와 수를 기록합니다.

Qrels가 후보 풀을 기반으로 작성되었거나 일부 문서만 판정했을 가능성을 확인합니다. 미판정 문서는 Recall 계산에서 정답으로 세지 않지만, 반드시 비관련 문서라고 단정하지 않습니다.

1차 평가에는 데이터셋의 질의와 Qrels를 사용하며 LLM을 통한 질의·정답 생성은 포함하지 않습니다. 청킹은 후속 실험으로 분리하고, 추가할 때 문서 단위 정답을 청크와 연결하는 평가 규칙을 별도 정의합니다.
