# KoBLEX 평가 규칙 v1

[데이터 흐름·스키마·매핑](data-flow.md) · [실행 안내](README.md) · [검증 결과](results-2026-10-24.md)

## 입력과 정답

- 검색 입력은 `background.strip() + '\n\n' + question.strip()`이다. 참고 답변·정답 근거·n_hops는 넣지 않는다.
- 매핑은 공백만 정리한 index·계층·전체 본문으로 판정한다. 단일 일치 또는 손실 없는 전체 본문 조합만 인정하고, 후보가 모호하면 보류한다.
- 법령 중복은 원본 `(index, hierarchy, content)`가 같은 행만 합치고 원문·원본 행 위치는 보존한다.
- `qrels[query_id][evidence_id] = [필요한 unit_id, ...]`이며, 근거 하나라도 미해결이면 질문 전체를 평가에서 제외한다.
- 질문별 고유 evidence ID를 근거 수로 사용한다. `n_hops`를 근거 수로 대체하지 않는다.

ID는 UTF-8 compact JSON의 SHA-256으로 만든다(`ensure_ascii=False`, 구분자 `(',', ':')`, 키 정렬 없음). unit은 `[코퍼스 revision, 원본 index, hierarchy, content]`, evidence는 공백 정리한 `[index, hierarchy, content]`를 해시하고 각각 `u_`, `e_`를 붙인다. 리비전이나 규칙을 바꾸면 기존 결과와 구분한다.

## 근거 회수와 점수

한 근거에 연결된 **모든 unit의 전체 본문**이 누적 상위 K 결과에 있어야 해당 근거를 회수한 것으로 센다. 제목·정답 ID만 있는 결과는 인정하지 않는다. 청크는 원문 문자 구간 `[start,end)`와 실제 본문을 검증하고, 구간 합집합이 unit 전체를 덮어야 한다. 중복 근거는 한 번만 세며 반복 청크도 순위를 소비한다.

| 지표 | 질문별 계산 |
| --- | --- |
| Evidence Recall@K | 회수한 고유 근거 수 / 정답 고유 근거 수 |
| Hit@K | 근거 하나 이상 회수하면 1, 아니면 0 |
| All-evidence Hit@K | 주석된 모든 근거를 회수하면 1, 아니면 0 |
| MRR | 첫 근거가 완성된 순위의 역수, 없으면 0 |

질문별 점수를 동일 가중치로 평균한다. 평가 대상 질문의 검색 결과가 없으면 빈 목록으로 0점 처리하고, 질문 자체가 누락되면 오류로 처리한다. 보류 질문은 분모에 넣지 않는다. K 기본값은 1/5/10/20/50/100이다. 평가 함수의 MRR은 입력 순위 전체 기준이므로 MRR@100을 보고하려면 먼저 100개로 제한한다.

## 분할과 설정

- 원본 분할과 내부 dev/test/holdout을 구분한다. test로 설정을 튜닝하지 않는다.
- 원본 ID 계열 또는 시나리오·검색 입력의 문자 n-gram 유사도로 연결된 질문은 같은 그룹에 둔다. seed 기반 그룹 순서로 dev 목표 비율에 가깝게 배정한다.
- 같은 그룹은 dev/test로 나누지 않는다. 보류 질문은 holdout에 두고 그룹 배정을 보존한다. 법령 코퍼스는 전체 공통이다.
- 경로·원본 파일 선택·분할 조건은 [koblex.toml](../../../configs/koblex.toml), 원본 리비전·해시는 [source manifest](source-manifest.json)에서 관리한다. 조건을 바꾼 결과는 기존 고정 분할과 구분한다.

법령 시점과 정답 근거의 완전성·필수/보조 구분은 확인되지 않았다. 점수는 이 고정 주석 집합의 회수 성능이며 현행법 정확도나 법률 전문가 검수 결과가 아니다. 상세 한계는 [검증 보고서](audit-report.md)에 남긴다.
