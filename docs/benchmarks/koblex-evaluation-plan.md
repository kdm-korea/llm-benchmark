# 1번 연구: KoBLEX 기반 평가 데이터와 정답 기준 구축

- 작성일: 2026-10-23 (Asia/Seoul)
- 프로젝트: llm-benchmark
- 상위 계획: [법률 RAG 연구 방향 및 실험 계획](../research-plan.md)
- 상태: 2026-10-23 평가 기반 v1 구축 완료. 원본 226문항 중 222문항 평가 가능·4문항 보류, dev 44·test 178. 임베딩·검색 성능 및 생성 평가는 미실행입니다.
- 실행 결과: [원본·정답 매핑 검증 보고서](koblex/audit-report.md), [검색 평가 계약](koblex/evaluation-rules.md), [답변 검수표](koblex/answer-rubric.md).

## 1. 목적과 결정 사항

법률 RAG의 법령 검색과 답변 생성을 평가할 수 있도록 기존 공개 테스트셋 KoBLEX를 우선 검증·활용합니다. 질문·정답을 처음부터 모두 새로 만들지 않고, 기존 데이터의 구조와 근거 연결을 확인한 뒤 부족한 유형만 추가합니다.

이번 1번 연구의 완료 범위는 평가 데이터, 정답 근거 매핑, 평가 규칙, 튜닝·최종 평가 분할을 확정하는 것입니다. 실제 청킹·임베딩 성능 비교와 답변 생성 실험은 이 산출물을 사용하는 다음 단계입니다.

## 2. 기존 실험과의 관계

| 구분 | 기존 완료 실험 | 이번에 준비할 평가 |
| --- | --- | --- |
| 데이터 | EVE-Bench-Legal-2.0 | KoBLEX |
| 검색 대상 | 한국어 판례 59,786개 | KoBLEX에서 제공하는 한국어 법령 코퍼스 |
| 질의 | 5,998개 | 공식 설명상 시나리오 기반 226개, 실제 파일 검증 필요 |
| 정답 | 관련 판례 문서 ID | 질문별 근거 조문·참고 답변, 실제 구조 확인 필요 |
| 평가 단위 | 판례 1개당 벡터 1개 | 근거 조문과 그에 연결되는 검색 단위 |
| 목표 | 판례 검색용 임베딩 모델 선정 | 법령 검색·복수 근거 회수·답변 평가의 기반 확보 |

기존에는 BGE-M3, KURE-v1, Multilingual E5 Large를 비교했고, 문서 단위 Recall@K·이진 nDCG@K가 가장 높은 KURE-v1을 기본 모델로 선택했습니다. 이 결과는 법령·조문 단위 검색에서도 가장 좋다는 의미가 아닙니다. 다음 단계의 기준선 모델로 사용하고 새 조건에서 성능을 확인합니다.

기존 결과는 [실험 결과 보고서](results/2026-10-20-embedding-recall.md)에 보존합니다. 판례 검색과 법령 검색의 점수를 같은 성능 척도로 직접 비교하지 않습니다.

## 3. KoBLEX를 선택한 이유와 확인된 정보

[KoBLEX 공식 저장소](https://github.com/daehuikim/KoBLEX)는 다음 구성을 설명합니다.

- 사건 시나리오, 질문, 답변, 근거 법조문을 포함한 226개 다단계 추론 QA
- LLM 생성과 전문가 수정·평가를 결합한 데이터 구축
- 별도로 제공하는 한국어 법령 코퍼스
- 질문과 근거 조문을 이용하는 검색·답변 평가 및 LF-Eval 평가 방법

공식 안내의 데이터셋 식별자는 다음과 같습니다.

| 역할 | 데이터셋 |
| --- | --- |
| 질문·답변·근거 | `JihyungL/KoBLEX-koblex` |
| 한국어 법령 코퍼스 | `JihyungL/KoBLEX-statute` |

공개 법령 뷰어에서는 `index`, `hierarchy`, `content` 필드를 확인했습니다. 공식 저장소는 한국어 법령을 항 수준으로 제공한다고 설명하지만, 뷰어에는 장·절 제목, 조 제목, 항·호 등 여러 구조가 보입니다. 모든 행이 동일한 단위이거나 `index`가 유일하다고 가정하지 않습니다.

QA 데이터셋의 직접 페이지 접근은 앞선 조사에서 확인되지 않았습니다. 공식 저장소의 제공 안내와 실제 다운로드 가능 여부를 구분하고, 로컬 검증에서 접근성과 필드 구조부터 확인합니다.

## 4. 이번 연구에서 답할 질문

1. 공개된 질문·답변·법령 코퍼스를 고정 리비전으로 확보할 수 있는가?
2. 질문별 근거 조문을 코퍼스의 실제 검색 단위와 모호함 없이 연결할 수 있는가?
3. 조·항·호 및 이후 생성할 청크 사이에서 정답 연결을 유지할 수 있는가?
4. 복수 근거를 일부 찾은 경우와 모두 찾은 경우를 구분해 평가할 수 있는가?
5. 동일 평가셋으로 검색 실패와 답변 생성 실패를 구분할 수 있는가?

## 5. 데이터 점검과 정답 매핑

| 점검 영역 | 수행할 작업 |
| --- | --- |
| 원본 고정 | QA·코퍼스 리비전, 파일 해시, 다운로드 시각, 라이선스·이용 조건 기록 |
| 스키마 | 실제 분할·행 수·필드·자료형, 질문·답변·근거 표현 방식 확인 |
| 식별자 | 질문과 코퍼스 ID의 중복·누락 확인, 필요한 경우 안정적인 내부 ID 부여 |
| 구조 | 장·절 제목과 실질 조문을 구분하고 조/항/호 계층 및 부모 관계 보존 |
| 근거 연결 | 근거 명칭·식별자·본문과 코퍼스 대조, 일대다·중복·누락·모호 매칭 기록 |
| 시점 | 법령 버전·시행일·사건 기준 날짜의 제공 여부 확인, 없는 값은 미확인으로 기록 |
| 품질 표본 | 단일·복수 근거, 유사 조문, 예외·단서 포함 사례를 원문과 대조 |

근거가 정확히 매핑되지 않는 질문은 임의로 정답을 추정하지 않습니다. 해결 여부·사유를 기록하고, 평가 가능 질문과 보류 질문의 수를 보고합니다. 빈 답변·빈 근거도 별도 검토합니다.

원본 정답이 전체 관련 조문을 빠짐없이 포함한다고 가정하지 않습니다. 미판정 조문은 비관련성이 입증된 조문과 구분하고, 정답 집합 밖의 검색 결과는 오류 분석에서 검토합니다.

## 6. 내부 평가 데이터 계약

다음은 프로젝트 내부 필드 제안입니다. 원본 KoBLEX의 실제 필드명은 다운로드 후 별도로 확인합니다.

| 데이터 | 내부 필드·역할 |
| --- | --- |
| 질문 | `query_id`, `scenario`, `question`, `retrieval_query`, `reference_answer` |
| 법령 | `unit_id`, `source_row_id`, `law_name`, `hierarchy`, `content`, `parent_id` |
| 정답 근거 | `query_id`, `evidence_id`, 원본 근거, 연결된 `unit_id`, 매칭 상태·판정 이유 |
| 분할 | 질문별 `dev`·`test`, 그룹 ID, 분할 규칙·seed |
| 추적 정보 | 원본 리비전·해시, 정규화 버전, 검토 상태, 확인 가능한 시점 정보 |

검색 입력은 원칙적으로 시나리오와 질문을 결합합니다. 참고 답변·정답 조문·설명은 검색 질의나 생성 프롬프트의 입력에 섞지 않습니다. 정답 조문을 직접 제공하는 생성 진단 실험은 별도 조건으로 구분합니다.

동일 조문을 여러 청크로 나누어도 원래 `evidence_id`를 유지합니다. 어느 정도의 본문 포함을 근거 회수로 인정할지 규칙을 정하고, 조문명만 등장하거나 제목만 검색된 경우를 본문 회수와 구분합니다. 같은 근거를 담은 중복 청크가 여러 개 검색돼도 근거 회수 수는 한 번만 셉니다.

## 7. 평가 기준

### 검색 평가

| 지표 | 의미 |
| --- | --- |
| Evidence Recall@K | 질문별 정답 근거 중 상위 K 결과가 회수한 근거 비율의 평균 |
| Hit@K | 정답 근거를 하나 이상 회수한 질문 비율 |
| All-evidence Hit@K | 제공된 정답 근거를 모두 회수한 질문 비율 |
| MRR | 첫 정답 근거가 등장하는 순위의 역수 평균 |

K는 우선 1/5/10/20/50/100을 후보로 두고 실제 코퍼스와 사용 목적에 맞춰 고정합니다. All-evidence Hit은 원본에서 필수 근거와 보조 근거를 구분하는지 먼저 확인합니다. 구분이 없으면 '주석된 모든 근거 회수'로만 해석합니다.

분할·매핑 규칙을 바꾼 경우 이전 수치와 구분합니다. 청킹 비교에서는 동일 K뿐 아니라 동일 입력 토큰 예산에서도 평가하고, 원래 법률 근거 단위의 Recall을 유지합니다. 문자 구간 정답이 없다면 구간 정확도를 이미 평가할 수 있다고 주장하지 않습니다.

### 답변 평가 준비

답변 정확성·완전성, 근거 충실성, 인용 정확성, 복수 조문 적용을 구분하는 평가표를 작성합니다. KoBLEX의 LF-Eval은 원 구현과 조건을 확인한 뒤 도입 여부를 결정합니다. 자동 평가 결과와 사람의 검토 표본을 함께 관리합니다.

다음 단계에서는 정답 근거를 제공한 생성 조건과 실제 검색 근거를 제공한 조건을 비교해 검색 오류와 생성 오류를 구분할 수 있도록 합니다. 이번 단계에서 생성 모델·프롬프트·합격 점수까지 임의로 확정하지 않습니다.

## 8. 분할과 재현성

원본 공개 분할을 확인합니다. 최종 평가용 데이터만 제공된다면 원본 분할 정보를 보존하고, 프로젝트의 튜닝용·최종 평가용 분할을 별도로 정의합니다. 유사 시나리오·중복 질문을 그룹화하고 가능한 경우 같은 그룹이 양쪽에 걸치지 않도록 합니다.

공유 조문은 실제 법률 검색에서 자연스럽게 발생하므로 중복 여부를 기록하되, 조문 공유만으로 무조건 질문을 제거하지 않습니다. 분할 기준과 한계를 명시하고 최종 평가셋으로 반복 튜닝하지 않습니다. 검색 코퍼스는 질문의 dev/test와 별개로 동일하게 유지합니다.

## 9. 산출물과 완료 기준

예정 산출물은 고정 원본과 manifest, 정규화된 질문·법령·정답 근거 연결, 분할 목록, 매핑 오류 목록, 데이터 점검 보고서, 평가 규칙입니다. 대용량 원본은 기존 프로젝트 방침에 따라 Git 추적에서 제외하고 공유 가능한 보고서와 설정을 남깁니다.

- [x] QA·법령 코퍼스 다운로드와 고정 리비전·해시 기록
- [x] 실제 스키마·행 수·분할·이용 조건 확인 (GitHub CC BY-NC 4.0, HF 별도 라이선스 명시 없음·적용 범위 미확인 기록)
- [x] 내부 ID와 법령 계층·중복 처리 규칙 확정 (구문상 부모만 추정, 미확인·복수 후보 보존)
- [x] 질문별 정답 근거 매핑 및 보류 질문·사유 집계 (222개 가능·4개 보류)
- [x] 시나리오·질문을 결합하는 검색 입력 규칙 확정
- [x] 튜닝·최종 평가 분할과 근거 회수 판정 규칙 확정
- [x] 검색 지표 정의와 답변 평가표 작성
- [x] 검수 표본 결과와 미해결 한계를 보고서에 기록 (17개 원문 점검, 독립 법률 전문가 검수는 미실시)

평가 기반 v1은 위 범위에서 구축했습니다. 4개 보류, 법령 시점 부재, 이용 조건의 명시 범위, 독립 의미 검수의 한계는 [검증 보고서](koblex/audit-report.md)에 남겼습니다. KURE-v1 검색 기준선은 다음 단계이며 이 문서의 완료 표시는 임베딩·생성 성능 실험 완료를 뜻하지 않습니다.

## 10. PDF 연구와 연결

KoBLEX는 법령 검색과 법률 답변 평가를 담당합니다. PDF 파싱·표·이미지·페이지 검색 평가는 별도의 RAG-Evaluation-Dataset-KO 법률 영역을 사용합니다. KoBLEX의 텍스트 시나리오를 PDF 원문 데이터로 해석하지 않습니다.

두 평가를 확보한 이후 PDF의 사실관계와 외부 법령을 함께 사용하는 질문·정답만 보완 구축합니다. 기존 PDF 질문에 KoBLEX 법령을 추가한 것만으로 법률 적용 평가가 성립한다고 가정하지 않습니다.
