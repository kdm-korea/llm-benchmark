## 1. 연구 목적

법률 문서에서 필요한 근거를 찾고 그 근거로 답하는 RAG(Retrieval-Augmented Generation, 검색 증강 생성)를 개발하려 한다. 임베딩, 문서 처리, 검색, 답변 생성의 각 단계에서 무엇을 비교하고 어떤 결과를 얻었는지 별도 테스트로 기록한다.

이 글은 전체 테스트의 역할과 순서를 안내한다. 개별 데이터의 매핑 규칙, 실험 조건, 결과는 각 테스트 글에 정리한다.

## 2. 테스트별 역할

| 단계 | 연구할 내용 | 판단할 질문 |
| --- | --- | --- |
| 1. 임베딩 모델 선정 | 같은 판례에 대한 모델별 검색 비교 | 관련 문서를 잘 찾는가? |
| 2. 평가 데이터와 정답 기준 | 질문·정답 근거·기대 답변 매핑 | 무엇을 정답으로 인정할 것인가? |
| 3. 법률 텍스트 청킹 | 조/항/호·문단·고정 길이 분할 | 필요한 맥락과 예외가 보존되는가? |
| 4. PDF 파싱 | 문단·읽기 순서·표·이미지 추출 | 원문 정보가 정확히 추출되는가? |
| 5. PDF 청킹·임베딩 | 페이지 경계와 문서 구조 처리 | 필요한 내용을 검색 가능한 단위로 표현하는가? |
| 6. 검색·재정렬 | 벡터·키워드·하이브리드·reranker 비교 | 답변에 필요한 근거가 상위에 모이는가? |
| 7. 근거 기반 답변 | 사실관계와 법령·판례를 결합 | 결론과 인용이 근거에 부합하는가? |


PDF 파싱은 원문 추출 정확성을, PDF 청킹은 추출된 내용의 분할 품질을 확인하는 별도 테스트다. 법률 텍스트 청킹, 검색·재정렬, 답변 생성 역시 각각의 비교 조건과 정답 기준을 갖는다. 앞 단계의 결과를 활용하더라도 한 테스트에서 다른 단계의 성능까지 검증한 것으로 해석하지 않는다.

## 3. 공통 평가 원칙

각 테스트는 판단할 질문과 변경할 요소를 먼저 정한다. 비교 대상에는 같은 입력과 정답 기준을 적용하고, 개발용 데이터로 설정을 정한 뒤 최종 평가용 데이터에서 결과를 확인한다.

원본 데이터와 적용한 도구의 버전·설정을 기록하고, 평균 점수와 실패 사례를 함께 남긴다. 개별 테스트의 지표·세부 판정 규칙은 해당 글에서 설명한다.

## 4. 테스트별 원고

- **판례 임베딩 검색 비교**: 동일 판례를 문서 단위로 검색한 모델별 Recall·nDCG 비교. [게시된 결과](https://kdm-korea.github.io/rag/embedding/2026/10/23/legal-embedding-recall-benchmark.html)
- **KoBLEX 테스트셋 생성**: 질문 근거와 법령의 매핑, 정답표, 개발·최종 평가용 분할 생성. 미게시 초안.
- **법률 텍스트 청킹·PDF 파싱·PDF 청킹·검색 및 재정렬·답변 생성**: 각각 별도 테스트와 결과 글로 정리할 예정.
