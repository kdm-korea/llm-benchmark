# 법률 RAG 연구 방향 및 실험 계획

- 작성일: 2026-10-23 (Asia/Seoul)
- 상태: 연구 계획. 완료 표시한 항목 외 실험은 아직 수행하지 않았습니다.

## 1. 연구 목적

법률 RAG 개발에 필요한 테스트와 연구 자료를 축적합니다. 법률 문서의 파싱·청킹·임베딩·검색·답변 생성을 단계별로 평가하고, 선택 근거와 실패 사례를 재현 가능한 형태로 기록합니다.

임베딩 모델 비교는 전체 연구의 첫 번째 실험입니다. 최종 목표는 PDF에서 필요한 내용을 찾고, 적절한 법령·판례를 근거로 검증 가능한 답변을 생성하는 것입니다.

## 3. 평가 데이터와 정답 기준

질문별로 다음 정보를 관리합니다.

- 질문 ID, 질문 유형, 출처, 문서 ID와 버전
- 정답 파일·페이지·근거 구간과 필요한 복수 근거
- 기대 답변과 허용 가능한 답변 범위
- 법률 적용이 필요한 경우 법령명·조문·시행일·사건 기준 날짜
- 근거 없음·정보 부족·상충 여부와 기대 대응
- 문단·표·이미지 등 근거 유형

문서 단위 정답만으로는 올바른 근거 청크를 찾았는지 판단하기 어렵습니다. 기존 문서 단위 평가는 유지하고, 페이지·근거 구간 정답을 추가합니다. 미판정 구간은 비관련성이 입증된 구간과 구분합니다.

튜닝용 질문과 최종 평가용 질문을 분리하고, 유사 질문·동일 문서가 분할 사이에 중복되는지 확인합니다. LLM으로 만든 질문·정답은 검토 상태를 기록합니다.

## 4. 법률 텍스트 청킹·임베딩

- 고정 토큰 길이, 문단, 조/항/호 구조 기반 청킹을 비교합니다.
- 청크 크기·중첩·제목 및 상위 조문 포함 여부를 비교합니다.
- 본문과 예외·단서·정의·부칙이 분리될 때 근거가 손실되는지 확인합니다.
- 인용 조문이나 관련 판례를 추가 검색해야 하는 질문을 포함합니다.
- 검색 청크와 답변에 제공할 상위 문맥의 범위를 비교합니다.
- KURE-v1을 기준선으로 사용하고, 청킹 조건을 확정한 뒤 비교 모델을 재검증합니다.

법령 데이터의 출처와 수집 범위는 별도로 선정합니다. 조문 식별자, 공포일·시행일, 개정 이력을 보존하고 특정 날짜에 적용할 버전을 구분합니다.

## 5. PDF 파싱·청킹·임베딩

파싱과 청킹을 분리해 평가합니다. 원문 추출 오류와 청크 분할 오류를 구분할 수 있도록 파싱 결과를 중간 산출물로 보존합니다.

| 영역 | 테스트 항목 |
| --- | --- |
| 텍스트 | 텍스트형·스캔형 PDF, OCR, 읽기 순서, 다단 구성, 머리말·꼬리말·각주 |
| 문단·페이지 | 페이지를 넘는 문단, 제목 계층, 페이지 기준과 문단 기준 청킹 비교 |
| 표 | 행·열 관계, 병합 셀, 단위·주석, 여러 페이지에 걸친 표 |
| 이미지 | OCR·설명문을 이용한 검색과 직접 이미지 임베딩의 필요성 비교 |
| 출처 | 파일·실제 PDF 페이지·인쇄 페이지·가능한 경우 좌표 추적 |

표·이미지 질문은 별도로 집계합니다. 평가 데이터에 스캔·다단·페이지 경계 등의 사례가 부족하면 보완 표본을 수집합니다.

## 6. 검색 방식과 법률 특성

- BM25, 벡터 검색, 하이브리드 검색을 동일 데이터로 비교합니다.
- reranker 적용 전후, 후보 수, 최종 근거 수, 중복 청크 제거를 비교합니다.
- 법령명·조문 번호·사건 번호의 정확 검색과 일상어 질문을 함께 평가합니다.
- 비슷한 문구의 다른 조문, 개정 전후 조문, 상충하거나 조건이 다른 근거를 포함합니다.
- 복수 조문·판례가 모두 필요한 질문에서 필수 근거의 회수율을 측정합니다.

## 7. 한국어 법률 PDF 기반 RAG 평가 및 외부 법령 결합 실험

### 데이터셋 후보

[allganize/RAG-Evaluation-Dataset-KO](https://huggingface.co/datasets/allganize/RAG-Evaluation-Dataset-KO)를 PDF 기반 평가의 시작점으로 사용합니다.

공식 README 설명 기준으로 법률 영역은 PDF 12개·291페이지, 질문 60개입니다. 질문의 근거 유형은 문단 40개·표 15개·이미지 5개입니다. 질문별 `target_file_name`, `target_page_no`, `target_answer`, `context_type`을 활용합니다.

위 수치는 공개 문서 기준이며 로컬 다운로드·행 수 검증은 아직 수행하지 않았습니다. 도입 시 데이터 리비전, 실제 질문과 문서 수, PDF 원본 링크의 접근성, 페이지 번호 기준, 이용 조건을 확인합니다. 원본 PDF와 해시를 보존하고 법률 범주 문서의 실제 구성도 점검합니다.

### 실험 구성

| 실험 | 검색 대상 | 목적과 정답 기준 |
| --- | --- | --- |
| A. 법령 검색 | 별도로 수집한 법령·조문 | 조/항/호 청킹과 관련 조문 검색 평가. 법령 질문·정답을 별도 구축 |
| B. PDF 기반 RAG | 데이터셋의 법률 PDF | 기존 질문·정답으로 파싱부터 검색·답변까지 평가 |
| C. 법령 + PDF 기반 RAG | 법령과 PDF | PDF의 사실관계와 법률 근거를 결합한 답변 평가. 적용 조문·기준 시점·기대 결론을 추가 작성 |

법령 수집·청킹·임베딩과 PDF 파싱·청킹·임베딩을 준비한 뒤, 각 자료의 출처 유형을 보존해 검색합니다. 두 자료를 결합하는 실험에서는 PDF 사실 추출, 법률 근거 검색, 사실관계에 대한 법률 적용을 구분해 평가합니다.

데이터셋의 기존 정답은 PDF 내용을 바탕으로 작성되었습니다. 기존 질문에 외부 법령을 추가하는 것만으로 법률 적용 능력이 평가되지는 않습니다. 원본 PDF 질의 평가와 추가 구축한 법률 적용 질의 평가를 구분합니다.

결합 효과는 동일한 법률 적용 질문에 PDF만 제공한 경우, 법령만 제공한 경우, 둘 다 제공한 경우를 비교합니다. 기존 PDF 질문에 대해서는 법령 추가가 검색과 답변을 방해하는지도 확인합니다.

### 평가 지표

| 평가 단계 | 지표·검토 기준 |
| --- | --- |
| 파싱 | 검수 표본의 텍스트 누락·오인식, 표 구조 보존, 원문 위치 정확성 |
| 파일·페이지 검색 | 정답 파일·페이지 Hit@K, 첫 정답 순위의 MRR |
| 근거 구간 검색 | 구간 정답 구축 후 근거 Recall·Precision, 필수 복수 근거 회수율 |
| 답변 | 정답 정확성·완전성, 제공 근거에 대한 충실성 |
| 인용 | 인용 위치의 존재, 주장 뒷받침 여부, 인용이 필요한 주장 누락 |
| 법률 적용 | 적용 법령·시점·요건·예외·결론의 적절성 |
| 실패 대응 | 근거 부족 시 유보, 추가 질문, 상충 근거 제시의 적절성 |

법률 질문 60개는 초기 비교용으로 사용합니다. 표·이미지 등 소규모 하위 집단은 성공 건수와 전체 건수를 함께 보고하고, 전체 법률 RAG 성능으로 일반화하지 않습니다. 자동 평가와 별도로 사람의 검토 표본을 둡니다.

## 8. 실패 상황과 운영성

- 정답 근거가 없는 질문, 사실관계가 부족한 질문, 서로 충돌하는 문서를 테스트합니다.
- PDF 본문에 포함된 명령문을 시스템 지시로 따르는지 확인합니다.
- 문서·법령 갱신 시 변경·삭제·구버전 구분과 재임베딩 범위를 확인합니다.
- 온라인 질의 지연시간, 임베딩 처리량, 메모리·인덱스 크기, 토큰 사용량·비용을 기록합니다.
- ANN을 도입하면 정확 검색 대비 검색 손실과 지연시간을 비교합니다.

## 9. 실험 통제와 기록

- 데이터·모델·파서·프롬프트·평가 기준의 버전과 실행 조건을 고정합니다.
- 청킹·검색 비교에서는 생성 모델과 질문을 유지하고 한 번에 한 요소씩 변경합니다.
- 청킹은 동일 K와 동일 입력 토큰 예산에서 각각 비교합니다.
- 질의별 검색 결과·점수·근거·답변·평가·오류 유형을 저장합니다.
- 평균과 함께 유형별 결과, 성공 건수, 가능한 경우 신뢰구간을 보고합니다.
- 최종 평가셋으로 반복 튜닝하지 않고 선택 근거와 적용 범위를 명시합니다.
