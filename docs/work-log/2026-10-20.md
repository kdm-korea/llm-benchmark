# 2026-10-20 작업 기록

## 요청과 목적

첫 실험에 비해 코드 계층이 많다는 피드백에 따라, 사용자가 승인한 네 모듈 구조로 단순화하고 가독성을 개선했습니다. 개발 문서·법률 도메인·시스템 프롬프트·참고 원본·작업 기록의 분리는 유지했습니다.

## 변경 사항

- 기존 실행 모듈 15개를 `dataset.py`, `embeddings.py`, `evaluation.py`, `run.py` 네 개로 정리했습니다. 패키지 초기화 파일은 집계에서 제외했습니다.
- `core`, `application`, `adapters`, `domains`, 빈 benchmarks 및 별도 CLI 폴더를 제거했습니다.
- `BenchmarkBackend`와 의존성 주입 구성을 없애고 `run_benchmark()`가 각 함수를 직접 호출하게 변경했습니다.
- 이미 계산한 순위를 MTEB 지표 함수에 직접 전달합니다. 같은 함수를 호출하기 위해 생성하던 Custom Task와 Dataset 변환을 제거했습니다.
- 긴 딕셔너리와 중첩 표현식을 펼치고, 장치 선택을 명시적인 분기로 변경했습니다.
- 중복된 Qrels 검증과 파일 체크섬 계산을 작은 공통 함수로 모았습니다.
- 질의 선택·임베딩·평가·저장의 흐름을 읽을 수 있도록 함수명과 설명을 정리했습니다.
- CLI 명령과 옵션, 원본 데이터와 캐시 키, 질의 ID, 결과 형식과 실패 기록을 유지했습니다.
- 테스트도 네 모듈에 대응하도록 정리하고, probe가 성능 점수를 보고하지 않는지 확인하는 테스트를 추가했습니다.
- 아키텍처, 실행 방법, README와 평가 설계를 현재 코드에 맞게 갱신했습니다. 제공 원본과 이전 날짜의 작업 기록은 수정하지 않았습니다.

## 검증

- 변경 전 기존 테스트 16개가 통과한 것을 확인하고, Recall·질의별 결과·MTEB 원본 결과·전체 데이터 검증 보고서를 임시 기준 파일로 저장했습니다.
- 변경 후 `.venv/bin/python -m pytest -q`: 기존 회귀 테스트와 probe 확인을 포함해 17개가 통과했습니다.
- 기존 Task 경유 결과와 새 직접 호출 결과의 JSON을 비교했습니다. Recall, 질의별 결과, 제외 질의, MTEB 원본 출력이 모두 동일했습니다.
- 실제 Corpus 59,786개·고유 질의 5,998개의 검증 보고서가 변경 전과 동일했습니다. 데이터 해시는 `8d8c00099c982267c656c386b48b822a589a20ef43678c30835fe931ae397408`입니다.
- `.venv/bin/uv sync --offline --cache-dir cache/uv`: 로컬 패키지와 새 CLI 진입점을 다시 설치했습니다. 의존성 추가나 네트워크 접근은 필요하지 않았습니다.
- `.venv/bin/embedding-benchmark --help`와 `prepare`, `.venv/bin/python -m embedding_benchmark.run --help`가 정상 동작했습니다.
- `.venv/bin/python -m compileall -q src`와 `.venv/bin/uv lock --check --offline --cache-dir cache/uv`를 통과했습니다.
- 실행 모듈 네 개와 구 계층 import 부재, Markdown 15개 및 로컬 링크 28개의 대상 존재를 확인했습니다.
- 보관된 참고 문서가 제공 원본과 바이트 단위로 동일함을 확인했습니다.

## 범위

이번 작업은 구조와 가독성 개선입니다. 모델을 다시 다운로드하거나 전체 Recall 벤치마크를 실행하지 않았습니다. 기존 데이터, 캐시, 추론 확인 보고서는 유지했습니다.


## Git 작업 규칙 문서 추가

- `docs/engineering/git-workflow.md`에 커밋 타입, 하이픈 브랜치 명명과 PR/Squash 병합 규칙을 작성하고 문서 목차에 연결했습니다.
- 리소스 커밋 타입은 `res+` 추가, `res-` 삭제, `res^` 변경입니다.
- 문서에서 리소스 전용 브랜치 규칙을 제거했습니다. `res+`, `res-`, `res^`는 커밋 메시지에만 적용하고 기존 하이픈 브랜치 규칙을 유지합니다.
- GitHub 업로드, 커밋 생성과 브랜치 생성은 수행하지 않았습니다.

- Git 작업 규칙에 기능별 브랜치·PR 분리와 최종 커밋 하나 원칙을 명시했습니다. 작업 중 여러 커밋은 Squash merge로 합치고 관련 코드·테스트·문서를 함께 포함합니다.


## Git 작업 스킬 생성 및 설치

- 사용자 스킬 경로 `~/.codex/skills/git-feature-workflow/SKILL.md`에 재사용 가능한 Git 작업 스킬을 생성·설치했습니다.
- 한국어 커밋 메시지, `res+` 추가·`res-` 삭제·`res^` 변경, 하이픈 브랜치명과 기능별 최종 커밋 하나 원칙을 포함했습니다.
- 질문·조회 응답은 work-log에 남기지 않으며, 커밋 요청을 원격 push·PR·병합 권한으로 확대하지 않도록 적용 범위를 명시했습니다.
- skill-creator의 quick_validate를 작성본과 설치본에 실행해 모두 통과했습니다. 기존 스킬을 덮어쓰지 않았고, 이번 작업에서 저장소 커밋·push·PR 생성은 수행하지 않았습니다.


## Git 스킬의 PR 요약 규칙 보완

- 설치된 `git-feature-workflow` 스킬에 PR 본문의 변경 목적·주요 변경 사항·실제 검증 결과를 한국어로 정리하도록 명시했습니다.
- PR 생성 후 채팅에도 주요 변경·검증 요약과 PR 링크를 함께 표시하도록 추가했습니다. 남은 작업·후속 작업·TODO 항목은 별도 추가하지 않도록 정리했습니다.
- 수정본과 설치본 모두 quick_validate를 통과했습니다.


## GitHub 업로드 준비와 검증

- GitHub의 `kdm-korea/llm-benchmark`가 커밋 없는 저장소임을 확인하고 로컬 Git 저장소를 초기화했습니다.
- PR 기준 브랜치를 만들기 위해 `main`에 파일 없는 초기 커밋 `chore: 저장소 초기화`를 올렸습니다.
- `feat-embedding-recall-benchmark` 작업 브랜치를 생성했습니다. 구현 코드·설정·테스트·문서를 기능 단위 커밋 하나로 정리합니다.
- `.venv/bin/python -m pytest -q`: 테스트 17개가 통과했습니다.
- `.venv/bin/uv lock --check --offline --cache-dir cache/uv`: 의존성 일치를 확인했습니다.
- Markdown 16개와 로컬 링크 29개를 검증했습니다.
- `.gitignore`에 따라 업로드 대상이 코드·설정·잠금 파일·문서와 빈 폴더 보존 파일뿐임을 확인했습니다. 모델·원본 데이터·벡터 캐시·실행 결과는 추적 대상에서 제외했습니다.
